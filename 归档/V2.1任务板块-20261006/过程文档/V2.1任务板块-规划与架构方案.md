## 二、★ 必须先解决：一个架构地雷

这是我这轮扫描发现的，**比任务板块本身更紧急**。

### 问题：分组标题是「按顺序猜」的，不是「按名字写」的

`app/js/app.js:189`：

```js
GROUP_NAME = { 1:'位置', 2:'收集', 3:'装备', 4:'地点', 5:'怪物' };
relIdx.forEach(function (g, i) {
  groupName[g] = GROUP_NAME[GROUP_ORDER[i]] || '其他';  // ← 靠下标猜
});
```

**用第几组来倒推它叫什么名字。** 我实测三层：

| 层 | groupIndex 集合 | 实际渲染结果 |
|---|---|---|
| 地上 | 0,1,2,3,4,**5** | 第 6 组 → 标题显示「**其他**」 |
| 地下 | 0,1,2,3,4,**5** | 同上 |
| 天空 | 0,1,2,3,4 | 5 组刚好对 |

**现在凑巧是对的** —— 因为 `catsOfLayer()` 过滤掉了「未命名」和 `count=0`，剩下恰好 5 组。

**但它经不起任何新增**：
- 我加一个「任务」组 → 某一层变成 6 组 → 第 6 组标题变「其他」
- 某天 `markers.js` 里多一个 count>0 的分类落到中间 → **全层标题整体错位**

后果是玩家看到「装备」下面写着「克洛格」，「地点」下面写着「武器」—— 现在没发生，但一加任务就可能发生。

### 修法（很小，但必须先做）

**给每个分类显式写 `groupName`，标题直接读它，不再按下标猜。**

```js
// catalogs.js 每条自带 groupCn:"位置" / "收集" / "装备" / "地点" / "怪物" / "任务"
groupName[g] = groups[g][0].groupCn || GROUP_NAME[GROUP_ORDER[i]] || '其他';
```

改动量：`catalogs.js` 加一个字段 + `app.js` 改 2 行。**加任何新组都不会再错位。**

## 三、规划主线：按「任务种类」，不按「流程档位」

这是你最后一个问题，也是最关键的。我的答案：

> **按任务种类（主线/支线/…）规划。流程档位（L1/L2/L3）是「渲染方式」，不是「组织方式」。**

理由：

1. **流程档位是数据缺失的产物，不是内容的分类。** 74 条能画线、86 条不能画，这是「攻略作者写没写到」决定的，跟任务本身是主线还是支线毫无关系。同一类里 30% 能画线、70% 不能，这个分类对玩家没有意义。
2. **玩家找任务时想的是「我要做什么」，不是「这条能不能画线」。** 玩家问的是「海拉鲁城堡的异变怎么过」，不是「这是 L1 还是 L2」。
3. **数据补齐后档位会变。** 今天 86 条没攻略，明天补上就是 L2 了。如果界面按档位组织，改一次动一次界面。

**所以：**
- **组织维度 = 任务种类**（来自 ROM 权威 `cat`，不是我们编的）
- **渲染维度 = 流程档位**（自动判定，用户看不到这个术语）

```
界面分组：主线(23) → 重要支线(66) → 普通支线(31) → 其他(166)
                ↓ 每个分类内部自动分流
        有多点坐标 → 显示流程按钮（点开画虚线）
        单点       → 直接显示攻略文字
        无坐标     → 只有任务名 + 前置/奖励
```

「挑战/小游戏」166 条里混着 `Other`（含小游戏）和 `ImportantMini`，这里有个细节要你定（见五）。

## 四、模块化架构：分 5 个模块，各自独立可回退

你担心「做着做着改乱了回退不了」—— 所以**每个模块单独一个文件、单独一次提交、单独一次验收**。任何一步不满意，只回退那一步，不影响已完成的。

```
app/data/
  tasks.js        ← 已完成（数据层，286 条，含流程坐标）
  armors.js       ← 已完成（135 件，套装拆分）

app/js/task/                       ← 新增目录，任务板块独占
  task-data.js       M1  数据接线层：把 tasks.js 规范化成渲染可用的索引
  task-classify.js   M2  分类判定层：任务种类分组 + 流程档位自动判定
  task-panel.js      M3  面板/卡片层：分类面板条目 + 任务卡片 + 流程线绘制
  task-flow.js       M4  流程模块：虚线 + P1/P2 编号（只被 M3 调用，可单独禁用）
  task-chain.js      M5  任务链模块：前置/解锁关系图（可单独关闭）

app/css/
  task.css           任务板块样式（独立前缀 .tk-，不污染现有样式）
```

**依赖方向单向**：`task-data → task-classify → task-panel → task-flow`。
M4/M5 是叶子，谁都不依赖，出问题直接拔掉。

**回退机制**：
- 每模块一个开关，写在 `layers.js` 或一个配置对象里
- `task-flow.js` 出问题 → 流程线消失，任务板块其他功能正常
- 最坏情况 → 删掉 `index.html` 里 task 那几行 `<script>`，**回到今天的状态**

**开发顺序**（每步做完你先验收）：

| 步 | 模块 | 做什么 | 你验收什么 |
|---|---|---|---|
| 0 | — | **分组标题去地雷**（M0） | 现有界面标题不变、点分类正常 |
| 1 | M1+M2 | 数据接线 + 分类判定（**只出 JSON 不渲染**） | 我给你打印分组结果，你确认分类对不对 |
| 2 | M3 | 面板 + 卡片（**只有单点任务上线**） | 点开卡片内容对不对 |
| 3 | M4 | 流程线（选中后才画） | 74 条流程线画得准不准 |
| 4 | M5 | 任务链 | 前置跳转有没有歧义 |

**M1/M2 只出数据不渲染**是关键设计 —— 分类逻辑如果错了，改一行重跑就行，不涉及界面。

## 五、要你拍板的 3 件事

`Other` 里混了两种东西：
- **真正的小游戏/赛事**（`*_MiniGame`、`BirdManContest`、`Circuit_*`，约 25 条）→ 你说放地点，但它们已在「地点」组的挑战分类里有了重复风险
- **其它支线/小任务**

选项：
- **A**：`Other` 整块作为一个子类「其他任务」（166 条一起，最省事）
- **B**：小游戏单列「小游戏」子类（25 条），其余 141 条为「其他任务」
- **C**：小游戏完全不进任务板块（因为地点组已有）

我倾向 **C** —— 跟你「挑战归地点」的判断一致，且避免同一点两次出现。

### ② 4 条重复 key

- **A**：合并成 1 条，卡片里列 4 段文本
- **B**：保留 4 条，靠地点/坐标区分

我倾向 **A**（界面上重复点没意义）。

### ③ M0 去地雷要不要先做？

- **A**：先做 M0（改 2 行 + 加字段，风险极低），再开工
