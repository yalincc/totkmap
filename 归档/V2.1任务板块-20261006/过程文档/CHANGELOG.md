> → M5 存档同步 → M5.1 完成态上地图。归档快照见 `归档/V2.1任务板块-20261006/`。

### 数据（M0–M1）
- 从 ROM `Quest` BGYML + 玩家攻略 `markers.js` 提取 **286 条**任务，
  排除 26 条小游戏（留在原地点分类）后**259 条**进任务板块。
- **官方分步清洗**：ROM `Steps` 是事件触发器数组，1077 步里 600 条是空壳、
  12 条重复、327 条含控制字符或动态变量占位符。清洗后 **463 步**（`tools/clean_steps.py`）。
  原始 `steps` 保留不动，展示层用新增的 `stepsUI`。
- 修`catalogs.js` 的 156 个分类标题错位（反向查 `groupCn` 改为按 `catOrder`）。
- 新增 `kindCn` 任务性质分类：迷你挑战 121 / 情节挑战 59 / 主线剧情 23 / 神庙探索 21/
  支线故事 17 / 收集要素 6 / 地区任务 6 / 背景事件 4，其中 175 条来自玩家攻略的可靠标记。
- 合并「一发入魂」重复条目：ROM 侧`HourseInnChallenge004`（一击入魂）与攻略侧
  `key=null` 孤儿条目是同一任务（坐标差 10米）。**必须合**——`key=null` 没有
  `Step_` 变量，玩家在游戏里做完地图上永远不会变绿。合并后 `key=null` 归零。

### 存档同步（M5，本板块最硬的成果）
任务进度**不需要新解析器**，就存在神庙那张 hash 表里：
```
键 = murmurHash3("Step_" + 任务key)
值 = 当前阶段名的哈希，末项固定 Complete（0x4c0a63f4，全局唯一）
```
-枚举取自 `marcrobledo/savegame-editors` 的 `zelda-totk.hashes.csv`，
  **285/285 全部命中，阶段反查 0 失败**；**259/259 任务零缺口**。
- 用真实 `progress.sav`（Ryujinx，2307656 字节 v1.1.x）+ 神庙/鸟望台数交叉印证，
  Python 与 JS 两套实现输出完全一致。
- `save-parser.js` 新增 `questDone()`；`app.js` 两个存档入口（文件 / 服务端）都灌入；
  `live-python` 的 `/progress` 响应带 `questDone` 字段（xnavi 同步链路可直接用）。

### 界面
- **任务卡片**：右上角复制 + 完成勾、类型行、进度行（显示「Complete 第 4/4 步」）、
  底部导航 / 追踪 / 标记完成。攻略要点为主体，官方分步作「任务原文」**条件折叠**
  （有攻略才折叠，没攻略就平铺 —— 不藏唯一可用内容）。
- **卡片可拖动**：顶部把手或卡片空白处均可拖，3px 阈值、视口夹取、
  点击点偏左则卡片弹到右侧（反之弹左）。
- **流程线**：多点 / 单点 / 仅列表三档，**仅在选中任务并主动点「追踪」后显示**
  （不开卡片就画线 = 地图杂乱）。只在本图层内连线，跨层提示节点数不画穿墙直线。
- **追踪模式**：关卡片（Esc 也算）后流程线留在地图上，重开点追踪才关。
- **完成态上地图（M5.1）**：任务点右上角打勾 + 整体降透明去饱和，
  已完成的自动退到背景、未完成的跳出来。tooltip 加 ✓ 前缀，与探索侧口径一致。

### 踩坑（改这块代码前必看）
- `TaskDone.status(key)` 的 `src==='save'` 语义是「读到存档数据了」而非「存档说它完成了」，
  **对未完成任务也返回 `'save'`**。判「存档已完成」必须同时判 `st.done`，
  否则 259 个任务全显示「已完成 ✓」且按钮全灰。
- `task-card.js` **没有 `render()` 函数**（只有 open/close），就地重绘用自己加的 `redraw()`。
- 改 `tasks.js`(400KB) / `task-plan.js`(530KB) **绝不能 `json.loads`+`dumps` 重写**：
  会毁掉 CRLF 和 `window.TOTK_TASKS=` 变量名。必须 `io.open(..., newline='')` + 字符串定点替换。
- 任务点绘制在 `task-panel.js` 的 `taskIconDot()`；`signature()` 不带完成态的话，
  标记完成后地图不会重绘（面板已实现 150ms 轮询比对，混入 `doneRev` 即可）。

## TOTKMAP V2.0.2 — 神庙卡片补全位置/注意事项/宝箱（2026-10-05）

### 新增
- **探索卡片新增三行**：位置 / 注意 / 宝箱。原本卡片只显示区域/塔域/坐标/试炼四行，
  而 `markers.js` 里 120 个地上神庙（cat 63）与 32 个天空神庙（cat 109）的 `desc`
  本就带完整的四段结构化信息（名称/位置/注意事项/宝箱），**此前完全没被显示** ——
  尤其是「注意事项」那一段，正是任务与解谜前置条件的关键信息。
- 「注意事项」较长时**默认折叠 2 行**，右侧「展开/收起」按钮；不足则不显示按钮。
- 配色沿用卡片既有风格：试炼金色、位置/宝箱常规白、注意事项橙色（提示性质）。

### 实现要点
- 新增 `parseDescSections(desc)` 按行首标签（兼容半角/全角冒号）拆成四段，
  替换原先只提取「名称」的正则；`parseTrial()` 保留为兼容包装。
- **`markers.js` 有 13 条 desc 含 HTML 标签**（`<div>宝箱位于…</div>` 等，本意是换行）。
  卡片用 `textContent` 注入（无注入风险），但标签会显示成字面文本，
  故新增 `plainify()` 把块级标签转空格、剥掉零散标签。
- 兜底：`<div>宝箱…</div>` 这种写法在剥标签后不再带「宝箱：」前缀，
  由续接逻辑识别并转成宝箱段的起点。
- 非神庙分类（鸟望台/迷你挑战/洞穴等）desc 格式不统一，解析结果为空 →
  对应行**自动隐藏**，卡片保持原紧凑外观，不误伤。

### 数据现状（120 地上 + 32 天空 = 152 个神庙）
- 四段齐全 143 个；其余 9 个是**数据本身缺某段**（宝箱信息多写在注意事项里），
  解析器已尽量兜住，文字无丢失。

### 验证
- Node 全量跑 152 个神庙：四段齐全 143 / 需折叠 34 / 全空 0
- 浏览器实测：卡片四行正确显示、展开→line-clamp 由 2 变 none、按钮文字切换「展开/收起」、
  天空层剧情神庙正常、迷你挑战等非神庙新增行全部隐藏、零 JS 错误

## TOTKMAP V2.0.1 — 修复分类选择切层丢失（2026-10-05）

### 修复
- **切层后分类选择被清空**：原先 `state.selected` 是不分层的单一对象，`switchLayer()` 每次切层都调
  `selectDefault()` 把它整个重建 → 用户在「地上」勾的驿站/村庄，切到地下再切回来就恢复成默认的
  神庙/鸟望台。`清空图层` 按钮与搜索跳转的自动勾选也同样受影响。
- **改法**：`state.selectedByLayer` 按层独立保存，`state.selected` 始终指向当前层那份
  （渲染逻辑零改动）。本层从未选过才回退默认分类。
- **顺带获得刷新保持**：落盘 `localStorage`（`totkmap_selected_v2`），刷新页面也记住各层选择。
- 三个层的选择互不干扰，切换来回均保持。
- **不涉及 file:// 兼容性问题**：地图数据全靠 `<script src>` 加载，file:// 可用；
  仅 Service Worker 缓存与实时定位/导航（需 http 环境）不可用。

### 验证
- 地上勾「村庄+驿站」→ 切地下 → 切回地上：仍是村庄+驿站 ✓
- 三层各自独立（地上村庄驿站 / 地下树根 / 天空神庙），互不串扰 ✓
- 刷新页面后仍是村庄+驿站 ✓
- 回归：龙轨迹跨层自动补勾正常（16 个箭头）、全选 2509 个标点、零 JS 错误 ✓

## V1.8.7 — 定位核心重构（方案 A：单一状态机 + 锁住就信零自动扫描）（2026-09-27）

### 变更（live-go/TOTKNavi 定位核心）
- **全量重写为单一状态机**：单个 goroutine 5Hz 循环，唯一写 `lock.addr`；删除 5 个并发事件源抢锁的补丁堆叠。

- **删除**：teleportCh / jitterCheck / badAddrs / badClusters / 组内 swap / watchShortlist 多 goroutine / betterX 多级策略 / verifyKnown / watchdog / motion scan。
- **保留**：块世代检测（游戏重启识别，3s 一查）、known_addrs 记忆（verified 后才写入）、/rescan。

- **正确解码方法**（参考 SwitchThemeInjector DDS.cpp 的 getAddrBlockLinear）：
  1. zstd 解压（带 ZsDic.pack 字典）
  2. 搜 `b'BRTI'` magic 定位
  3. Format 在 BRTI+28，Width 在 +36，Height 在 +40，BlockHeightLog2 在 +52
  4. PtrsAddress 在 BRTI+112（int64），其指向第一个 int64 = data offset（通常 0x1000）
  5. 用 `texture2ddecoder.decode_astc(data, w, h, 4, 4)` 解码
  6. **关键：必须做 Tegra block-linear untile**，公式：
     ```
     def get_addr_block_linear(x, y, img_w_blocks, bpp, base, block_height):
         gw = (img_w_blocks * bpp + 63) // 64
         gob_addr = base + (y // (8*block_height)) * 512 * block_height * gw \
                        + (x * bpp // 64) * 512 * block_height \
                        + (y % (8*block_height) // 8) * 512
         x *= bpp
         return gob_addr + ((x%64)//32)*256 + ((y%8)//2)*64 + ((x%32)//16)*32 + (y%2)*16 + (x%16)
     ```
