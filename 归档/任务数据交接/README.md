## 4. ★ 数据缺陷清单（需要清洗的重点）

### 缺陷 1：字段值里混进了后续字段（2 条，必须修）

`desc` 没按 `\n` 拆，导致「前置任务」的值为整段文本：

| 任务 | 症状 |
|---|---|
| `乘在妖兽上的公主` | 前置任务 = `需要先完成"调查真相！…！！" 【开启任务】…【注意事项】…【任务奖励】卢比` |
| `六龙御前` | 注意事项 = `星标所在位置斩击（水技能）【任务奖励】蛋白石*5` |

→ 需要按 `【字段名】` 正则重新切分，值里若出现 `【...】` 就说明串了。

### 缺陷 2：一个字段里塞了多个任务（9 处，需拆成数组）

用「、」「，」「,」「/」分隔的多个任务名：

```
调查德依布朗遗迹吧 → 解锁任务 = "被众龙所守望的枭、两龙之间的夹缝、六龙御前、身体纤长的守护龙"
献给弥佳的小夜曲   → 前置任务 = "调查真相！传言中的塞尔达公主、圆号乐手的脱逃剧"
第八位英雄         → 前置任务 = "英雄们的秘密，和提克尔比试，迷路的商队队员"
```

→ 建议拆成数组：`["被众龙所守望的枭", "两龙之间的夹缝", ...]`

### 缺陷 3：值里混入 HTML 与玩家备注（1 处）

```
很冷哦！忍耐力大比拼 → 解锁任务 = "无<div>P.s. 背一把火属性的武器就行啦，不用浪费药…</div>"
```

→ 剥标签，「P.s.」开头的备注应单独抽出或删除。

### 缺陷 4：任务链引用**大部分匹配不上**

用任务名做键去匹配本集合（**注意分母是"有该字段的条数"，不是 170**）：

| 字段 | 有值条数 | 能匹配上 | 比例 |
|---|---|---|---|
| 前置任务 | 124 | 21 | **17%** |
| 解锁任务 | 111 | 9 | **8%** |

> 匹配率这么低，说明**不能把这两个字段直接当任务链用**（详见缺陷 5）。
> 大部分引用指向本集合外的任务（主要是「回忆」类），或是条件描述而非任务名。

匹配不上的原因：
1. **指向的是本集合外的任务**（如「调查真相！传言中的塞尔达公主」是「回忆」类任务，
   `markers.js` 里没有独立标点）
2. **指向的是任务名而非"去下一个地点"**，语义混杂（见下方「语义混杂」）

### 缺陷 5：★ 语义混杂 —— 前置/解锁字段含义不统一（**最重要的发现**）

同一个字段里混着两种完全不同的语义，**这是清洗时最需要判断的地方**：

**A. 真正的任务依赖**（可串成链）
```
为奥尔汀带来和平  →前置: 无              →解锁: 为阿卡莱带来和平
为阿卡莱带来和平  →前置: 为奥尔汀带来和平  →解锁: 为海拉鲁平原带来和平
寻找！魔犹伊的遗失物 →前置: 无            →解锁: 科尔天的下落
```
「为阿卡莱带来和平 → 为海拉鲁平原带来和平」是希顿族三兄弟任务的**真实顺序链**。

**B. 实际是"需要去这个地点"**（不是任务名）
```
老师，教教我吧！2 → 前置任务: 老师，教教我吧！1     ← 真依赖
调查德依布朗遗迹吧 → 前置任务: 需要解锁四个贤者，不然不出现石碑  ← 实际是条件描述
未知的天空巨人…    → 前置任务: 岩石巨人、西诺克斯、莫尔德拉吉克WANTED  ← 实际是"击败这些敌人"
```

→ **建议**：为每个字段加一个 `type` 标记（如 `"quest"` / `"condition"` / `"unknown"`），
由处理方判断，**不要强行当成任务链**。

### 缺陷 6：文本里有错别字（人工录入未校对）

| 错字 | 应为 |
|---|---|
| 左纳尼乌姆 | 左纳乌尼姆 |
| 右纳尼乌姆 | 右纳乌尼姆 |
| 莫力布林 | 莫力布（怪物名） |
| 余料 | 布料（任务奖励里出现） |
| 「拉姆达」 | 拉姆达（人名，出现在任务名里，需确认官方译名） |

### 缺陷 7：描述里有零散的口语/冗余表述

统计「点击」「查看攻略」等字样在**任务数据里是 0 处**（这类残留主要在神庙/鸟望台等其他分类）。
但任务文本里有口语化表述（"建议多观察"、"勤使用通天术"）与网页来源痕迹（HTML 标签，见缺陷 3）。
→ 清洗时可一并规范化，去掉口语冗余。

### 缺陷 8：其他分类的同类问题（顺带提示，不属本次范围）

「点击左下角查看攻略」这类**网页残留主要出现在神庙、鸟望台、迷你挑战之外的分类**，
例如神庙 desc 里的「详情可点击左下角的查看攻略，进行查看」。
若后续也要把这些分类接入卡片，同一套清洗规则可复用。

## 5. 数据可靠性评估（给处理方判断用）

**这些数据是从 V1.4.2 就存在的社区攻略整理文本，不是从游戏 ROM 提取的**，特征：

- 中文人工撰写，口语化（"建议多观察地图"、"勤使用通天术"）
- 带 HTML 标签（`<div>` `<p>` `<br>`）→ **明显是从网页复制粘贴的**
- 存在错别字与不一致的译名（见缺陷 6）
- 部分描述可能已过时（游戏 1.2.1 前后有改动）

**结论**：内容整体可信（170 条任务不可能凭空编造，且任务链顺序与游戏实际一致），
但**不能当作权威数据源**，错别字和过时描述需要人工校对。

**如果要权威数据**，需从 ROM 提取（`G:\YUZU\Switch Games\TOTKroms`）：
- `Banc/Quest/` 目录下的任务定义 BGYML（任务名、类型、阶段、Reward）
- 存档 `progress.sav` 里的 quest 哈希（可判断"这个任务你做没做完"）
> 这条路工作量大得多，建议先把现有数据用起来。

## 6. 建议产出格式

清洗后建议输出 `app/data/tasks.js`（与现有数据风格一致，`window.TOTK_TASKS=[...]`）：

```json
{
  "id": 1770,
  "name": "为阿卡莱带来和平",
  "layer": 18,
  "x": 1234.5,
  "y": -567.8,
  "questType": "story",              // story(情节挑战) | side(迷你挑战)
  "start":  { "type": "quest", "text": "与霍司塔对话" },
  "note":   "将前方的怪物营地清除",
  "reward": ["卢比"],
    "requires": [                       // 前置依赖
      { "type": "quest", "name": "为奥尔汀带来和平", "resolved": true }
    ],
    "unlocks": [                        // 解锁的后续
      { "type": "quest", "name": "为海拉鲁平原带来和平", "resolved": true }
    ],
    "raw": { /* 原始五字段，便于追溯 */ }
}
```

要点：
- `requires` / `unlocks` 用**数组**（原字段有多值缺陷）
- 每项带 `type`（`quest` / `condition`）区分语义（见缺陷 5）
- `resolved` 标记该引用是否在本集合内解析成功（**当前前置 17% / 解锁 8%**）
- 保留 `raw` 原始字段，便于回溯
